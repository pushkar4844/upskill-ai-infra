Concept primer

Server hardware and topology

Performance depends on where things sit: which CPU socket, which PCIe switch, which NIC. Topology decides whether data takes the short path or crosses the system.

Key ideas

  1. Read nvidia-smi topo -m: PIX/PXB means the same PCIe switch tree, PHB the same host bridge, NODE the same NUMA node, SYS crosses CPU sockets (slowest), NV# means NVLink.
  2. NUMA: a GPU and its NIC belong to one CPU socket. A process or buffer on the other socket makes every copy cross the inter-socket link.
  3. PCIe links can train down silently (x16 to x8, Gen5 to Gen3). Compare LnkCap with LnkSta under load and check AER error counters.
  4. GPUDirect RDMA lets a NIC read and write GPU memory directly. It needs the GPU and NIC under the same root complex (ideally the same switch), IOMMU off or in pass-through, and the peer-memory module.
  5. In HGX systems, eight GPUs connect through NVSwitch for all-to-all NVLink bandwidth inside the node; the NICs (usually one per GPU) carry traffic between nodes.

Common mistakes

  • Checking PCIe link speed while the GPU is idle (it downclocks)
  • Binding ranks to the wrong NUMA node
  • Expecting cloud VMs to expose every PCIe detail that bare metal does

What interviewers probe

Draw an 8-GPU HGX node. A GPU shows half the expected PCIe bandwidth: what do you check?

  • Linux tools: dmesg, journalctl, lspci, numactl, ethtool, iostat, perf, nvidia-smi, ipmitool

Terms

AER
PCIe Advanced Error Reporting: kernel counters and messages for correctable and uncorrectable PCIe errors.
HGX
NVIDIA's multi-GPU server baseboard design (e.g. 8 GPUs connected by NVSwitch).
NUMA
Non-Uniform Memory Access: memory and devices attached to one CPU socket are faster for that socket.
NVLink / NVSwitch
NVIDIA's high-bandwidth GPU-to-GPU links and the switch chips that connect all GPUs in a node.
