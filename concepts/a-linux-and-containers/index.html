Concept primer

Linux and containers

Every GPU problem shows up first as a Linux symptom: a slow node, a missing device, a stuck process. You need a fixed order of checks and a clear picture of how a GPU reaches a container.

Key ideas

  1. USE method: for every resource (CPU, memory, disk, network, GPU) check utilization, saturation and errors. It turns 'the node is slow' into a checklist.
  2. Low GPU utilization usually means the GPU is waiting: for data loading, host-to-device copies, CPU work or communication. Look at the CPU side before blaming the GPU.
  3. A GPU reaches a container through the NVIDIA Container Toolkit: device nodes (/dev/nvidia*), host driver libraries and cgroup device rules are injected at start. CDI (Container Device Interface) is the newer, declarative way to describe them.
  4. The kernel module and the user-space driver libraries must be the same version. 'Driver/library version mismatch' means one was upgraded without the other being reloaded.
  5. Persistence mode (nvidia-persistenced) keeps the driver initialised, so the first CUDA call doesn't pay a multi-second start-up cost.

Common mistakes

  • Reading 'free' memory instead of 'available'
  • Upgrading the driver on a node without draining it first
  • Assuming the WSL2 virtual NIC behaves like a real one (use a VM for NIC and RDMA work)

What interviewers probe

A node is slow: what do you run first, and what does each command rule out? Walk from kubectl apply to a GPU visible inside the pod.

Practise it

  1. A1The 60-second node triage drillLearn the first commands you run on any slow node, and what each one rules out. You will create each bottleneck yourself, so you know what it looks like. Phase 1Core5 hL
  2. A2Flame-graph a stalled GPU jobGPU at 40% usually means the GPU is waiting for the CPU. Prove it with a flame graph, fix it, prove the fix. Phase 26 hG1
  3. A3Trace a GPU container end to endUnderstand exactly how a GPU appears inside a container: runtime hook, device nodes, cgroup allow-list, CDI. Phase 2Core6 hG1
  4. A4Driver lifecycle and version matrixDriver upgrades are the riskiest routine operation in a GPU fleet. Learn installation paths, persistence mode and the classic version-mismatch error. Phase 28 hG1

In the job posting

  • CUDA, NCCL, NVSwitch/NVLink, drivers, performance tuning
  • Linux tools: dmesg, journalctl, lspci, numactl, ethtool, iostat, perf, nvidia-smi, ipmitool
  • Linux fundamentals: drivers, kernel subsystems, cgroups, containers
  • Find bottlenecks at cluster, node, accelerator, network, application layers

Terms

CDI
Container Device Interface: a declarative spec describing device nodes and mounts for a container runtime.
