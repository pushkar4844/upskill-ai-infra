Concept primer

LLM and training literacy

You don't need to train models, but you must do the arithmetic and speak the workload's language: memory, compute, parallelism and serving metrics.

Key ideas

  1. Training memory with mixed precision and Adam is about 16 bytes per parameter before activations: a 70B model needs about 1.1 TB of state.
  2. KV cache per token = 2 x layers x KV heads x head dimension x bytes. It grows with context and concurrency and usually sets the serving batch size.
  3. Training compute is about 6 x parameters x tokens FLOPs. MFU (model FLOPs utilisation) = achieved / peak; 35-50% is typical for well-tuned large jobs.
  4. Parallelism: data parallel / FSDP shards state, tensor parallel splits layers (needs NVLink), pipeline parallel splits stages, expert parallel uses all-to-all.
  5. Serving metrics: time to first token (prefill), inter-token latency (decode), throughput. Disaggregated serving puts prefill and decode on separate GPUs and moves the KV cache over the fabric.

Common mistakes

  • Tensor parallelism across PCIe-only GPUs
  • Ignoring checkpoint cost when estimating useful training time
  • Quoting tokens/s without the batch size and context length

What interviewers probe

Can a 70B model train on one 8x80 GB node? Show the maths. MFU is 25%: where do you look?

Terms

KV cache
Stored attention keys and values for generated tokens; its size per token sets how many sequences fit on a GPU.
MFU
Model FLOPs Utilization: achieved model FLOPs divided by the hardware's peak FLOPs.
TTFT / ITL
Time to first token and inter-token latency: the two main latency metrics for LLM serving.
Young/Daly interval
Optimal checkpoint interval ~ sqrt(2 x checkpoint cost x mean time between failures).
