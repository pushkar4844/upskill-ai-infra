Concept primer

Cloud, capacity and storage

Customers rent GPUs from clouds. Knowing what each cloud really gives you (NICs per GPU, fabric, placement, quotas, storage) is what separates a cloud-aware architect from a hardware specialist.

Key ideas

  1. The same GPU can perform differently across clouds: NIC count and speed per GPU, fabric type and NCCL plugin, rail design and placement all matter.
  2. Capacity is a project in itself: quotas, capacity reservations or blocks, placement groups and per-zone limits come before any Terraform.
  3. Storage tiers: object store (source of truth), local NVMe (cache), parallel file system (shared high throughput). Model load and checkpoint time are storage problems.
  4. Large rollouts go in waves with entry and exit criteria, a spare pool and a rollback plan.

Common mistakes

  • Requesting the Spot quota when you launch On-Demand (they are separate)
  • Spreading one training job across zones
  • Forgetting checkpoint write time when sizing storage

What interviewers probe

Why do two clouds with the same GPU give different all-reduce numbers? You have four weeks to bring up 1,024 GPUs: what is your plan?

Practise it

  1. I1Decode GPU instances and fabrics across cloudsBe the person who knows what each cloud really gives you per GPU instance. Phase 2Core8 hL
  2. I2Land 1,024 GPUs: capacity, placement and rollout planThe SA job in one document: take a customer from 'we bought 1,024 GPUs' to production in waves. Phase 310 hL
  3. I3Storage for model load and checkpointsModel load time and checkpoint stalls are infra problems. Measure storage tiers and recommend a design. Phase 312 hG4

In the job posting

  • Find bottlenecks at cluster, node, accelerator, network, application layers
  • Stand-out: hyperscaler compute and networking knowledge
  • Stand-out: multi-team leadership, executive communication
  • Stand-out: pilot to high-volume deployment record
