About this phase

Every later lab assumes three things: a Linux shell on your laptop, a cloud account that cannot surprise you with a bill, and Terraform files that create and destroy each lab environment in minutes. This phase builds all three once, so the rest of the roadmap is about learning, not plumbing.

You will not touch a GPU problem yet. You install WSL2 and the Kubernetes tool chain, open a separate AWS account with a budget alarm, request GPU quota (it can take a few days, which is why it happens on day 1), and write the Terraform for four environments: two small VMs, one GPU spot instance, a multi-GPU node and two EFA nodes.

The most important thing you learn here is a habit: every session ends with terraform destroy and a labdown check that prints an empty table. That habit is what keeps the whole roadmap at a few hundred dollars.

What you'll learn

A Linux workstation on Windows

WSL2 Ubuntu 24.04 with Docker, kind, kubectl, helm and k9s: the same tools you will use against real clusters.

Cloud guard-rails

A separate lab account, MFA, a budget alarm, a region choice and GPU quota requests for both On-Demand and Spot (they are different quotas).

Infrastructure as code for labs

Terraform templates for VMs, a GPU spot instance and two EFA nodes in a cluster placement group, reached through SSM instead of open SSH ports.

Cost discipline

Spot first, destroy every night, check for leftovers. Plus free and cheap alternatives for GPU time.

Setup stepsDo them in order. S1–S6 on day 1, the Terraform files (S7–S9) when you first need them.
  1. S1Install WSL2 + Ubuntu 24.04 on WindowsYour Windows laptop becomes a Linux workstation.
  2. S2Base tools inside Ubuntu (WSL)Everything below runs in the Ubuntu terminal, not PowerShell..
  3. S3Docker, kind, kubectl, helm, k9sInstall Docker Desktop for Windows and enable Settings > Resources > WSL integration > Ubuntu-24.04.
  4. S4AWS sandbox account with guard-rails (do this before any GPU)Use a separate AWS account (or one only for this lab), never a customer account.
  5. S5Request GPU quota (takes 1-3 days - do it on day 1)New accounts usually have 0 vCPU for GPU instances.
  6. S6Install Terraform and create your portfolio repoEverything you build goes into one Git repo.
  7. S7Terraform: two small Linux VMs (environment V)Save as ~/gpu-lab/infra/vms/main.tf.
  8. S8Terraform: one GPU spot instance (environment G1 / G4)Save as ~/gpu-lab/infra/gpu1/main.tf.
  9. S9Terraform: two EFA nodes (environment G2N) - only when you reach E2/F2Copy infra/gpu1 to infra/efa2 and change: count = 2, instance_type = an EFA-capable GPU size (check with the first command below; g4dn.12xlarge is the usual low-cost choice), a cluster placement group, and an EFA network interface instead of subnet_id/vpc_security_group_ids.
  10. S10The nightly teardown habit (most important rule)GPU labs get expensive only when you forget them.
  11. S11Free and alternative GPU accessSome labs need hardware AWS spot cannot give cheaply (MIG on A100/H100, NVLink/NVSwitch, InfiniBand).

The six lab environments

Laptop, VMs, one spot GPU, a multi-GPU node, two EFA nodes, rented A100/H100. Every lab says which one it needs.

By the end you can

  • WSL2 Ubuntu with Docker, kind, kubectl, helm, Terraform and the AWS CLI
  • A separate AWS lab account with a budget alarm and GPU quota requested
  • Terraform files for two Linux VMs, one GPU instance and two EFA nodes
  • A gpu-lab Git repository that will hold every script, result and note

How the phase runs

  1. Evening 1

    S1–S6: WSL2, base tools, Docker and Kubernetes CLIs, the AWS sandbox, quota requests and your gpu-lab repository.

  2. When needed

    S7–S9: the Terraform files. Write S7 and S8 now; S9 (EFA nodes) only when you reach labs E2 and F2.

  3. Every session

    S10: teardown and the labdown check. S11 lists free and alternative GPU options.

Tips

  • Request GPU quota first thing: approval can take 1–3 days.
  • Never put access keys in the repo. Use aws configure sso or a profile, and keep .tfstate out of git.
  • Tag every resource with project=gpu-lab so labdown can find leftovers.
