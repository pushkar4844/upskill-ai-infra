1 Phase 1 · Foundations

  1. A1The 60-second node triage drillLearn the first commands you run on any slow node, and what each one rules out. You will create each bottleneck yourself, so you know what it looks like. Core5 hL
  2. B1Build an XID decoderXID errors are how the NVIDIA driver reports GPU problems in the kernel log. You will build a tool that reads them and tells an operator what to do. No GPU needed. Core5 hL
  3. K1Transformer and cluster arithmeticInfrastructure people must do the math customers ask about: does the model fit, how big is the KV cache, how many GPU-days. You'll build a notebook you can reuse in interviews. Core8 hL
  4. C1Draw the node from memoryKnow which GPU sits next to which CPU socket and NIC. Every performance discussion (NUMA, GPUDirect, NCCL) starts from this picture. Core5 hG4
  5. B2DCGM diagnostics, levels 1 to 4DCGM is NVIDIA's data-center GPU manager. Its diag levels are how fleets prove a GPU is healthy. Learn what each level runs and how long it takes. Core6 hG1
  6. D1Redfish 101 on a mockup serverRedfish is the REST API every modern server BMC exposes (power, temps, fans, logs, firmware). You'll learn it with no hardware using DMTF's mockup server. Core5 hL
  7. E1RDMA from zero on Soft-RoCERDMA lets one machine write into another's memory without the remote CPU. It's what InfiniBand/RoCE/EFA give NCCL. Soft-RoCE emulates it in software on any NIC, so you learn the commands and concepts for free. Core6 hV
  8. F1nccl-tests on one node and the busbw formulaNCCL is the library that moves data between GPUs for training. nccl-tests measures it. Learn to run it, read algbw vs busbw, and plot results. Core6 hG4
  9. G1Slurm in Docker with fake GPUsSlurm is the HPC scheduler used for most large training clusters. Learn the daily commands and how GPUs are declared (GRES) on a laptop. 6 hL
  10. H1GPU Operator on one nodeOn Kubernetes, NVIDIA's GPU Operator installs everything a node needs for GPUs. Learn what it deploys, in what order, and how a pod gets a GPU. Core6 hG1

2 Phase 2 · Practitioner

  1. A2Flame-graph a stalled GPU jobGPU at 40% usually means the GPU is waiting for the CPU. Prove it with a flame graph, fix it, prove the fix. 6 hG1
  2. A3Trace a GPU container end to endUnderstand exactly how a GPU appears inside a container: runtime hook, device nodes, cgroup allow-list, CDI. Core6 hG1
  3. A4Driver lifecycle and version matrixDriver upgrades are the riskiest routine operation in a GPU fleet. Learn installation paths, persistence mode and the classic version-mismatch error. 8 hG1
  4. B3Burn-in and thermal or power throttlingNew GPUs are stressed for hours before customers get them. Learn to burn in, log clocks/temps/power, and spot throttling. Core8 hG1
  5. B4Automated quarantine with NVSentinel (exploratory)Read and run NVIDIA's open-source fault detection + remediation system. Understand the design even if you can't trigger real hardware faults. 8 hG1
  6. C2Measure the NUMA mis-pinning penaltyShow with numbers why a GPU's process must run on the CPU socket closest to it. Core5 hG4
  7. C3PCIe link health, AER, ACS and IOMMUA GPU running at x8 or Gen3 instead of x16 Gen4/5 silently halves bandwidth. Build a checker. Core6 hG1
  8. D2Boot OpenBMC in QEMU and talk to it two waysSee a BMC from the inside: boot real OpenBMC firmware in an emulator, query it with Redfish and IPMI. 8 hV
  9. E2EFA on AWS, validated like a field engineer wouldBring up two EFA nodes, prove EFA is used by NCCL, and record the version matrix. Core10 hG2N
  10. E3InfiniBand diagnostics cheat sheet (study task)InfiniBand can't be emulated cheaply. Learn the tools and counters well enough to read real output, then confirm on borrowed hardware. Core8 hL
  11. E5GPUDirect RDMA and the storage pathProve data goes NIC <-> GPU memory directly and see topology affect it. Needs ConnectX or EFA nodes that support GPUDirect RDMA (e.g. AWS p4d/p5) - usually rented or borrowed. 8 hR
  12. F2Scale 1 to 2 nodes, with and without EFAMeasure how all-reduce scales across nodes and what the fabric is worth. Core10 hG2N
  13. F3Debug a hang and a stragglerReproduce the two most common distributed-training incidents and learn to diagnose them. Core10 hG4
  14. G2Slurm on real GPU nodes with containers and health checksA real single-node Slurm with GPUs, container jobs (Pyxis/Enroot) and Node Health Check. Core12 hG4
  15. G3Provision the same cluster on three cloudsKnow how each hyperscaler builds HPC/AI clusters. Build one for real (AWS ParallelCluster), read the other two. 14 hG2N
  16. G5Rack to OS: PXE-boot a cluster you builtSee how a bare server becomes a node: DHCP, PXE/iPXE, kernel+image, config. Uses VirtualBox on your laptop, no nested virtualization needed. 12 hL
  17. H2GPU sharing: time-slicing, MPS and MIGKnow the three ways to share a GPU and when each is right. 8 hR
  18. H3Network Operator and RDMA in podsUnderstand how pods get RDMA NICs: Network Operator, Multus, SR-IOV/shared device plugins. 10 hL
  19. H4Gang scheduling, quota and topology on fake nodesPractice multi-tenant GPU scheduling (quota, borrowing, all-or-nothing start) with 100 fake GPU nodes on a laptop. Core10 hL
  20. H5Dynamic Resource Allocation (DRA)DRA is the new Kubernetes model for devices: claims with attributes instead of a simple count. Learn it with the example driver. 8 hL
  21. I1Decode GPU instances and fabrics across cloudsBe the person who knows what each cloud really gives you per GPU instance. Core8 hL
  22. J1GPU metrics pipeline end to enddcgm-exporter -> Prometheus -> Grafana -> alerts. The observability stack every GPU platform runs. Core8 hG1
  23. K2Parallelism and MFU on real hardwareRun a real training recipe, compute MFU, and connect it to the NCCL numbers you measured. 12 hG4
  24. K3Checkpointing and failure recovery mathKnow how often large jobs fail and how often they should checkpoint. 8 hG4
  25. K4Know the workload: serving side, kept shortCustomers ask about inference. Serve a model with vLLM, measure TTFT/ITL/throughput, connect it to infra needs. 8 hG1

3 Phase 3 · Senior: design and operate at scale

  1. B5Write the cluster acceptance runbookThe document a customer signs before taking a GPU cluster: stages, thresholds, evidence, go/no-go. Your strongest interview artifact. Core16 hG2N
  2. C4Golden BIOS and firmware baselineDetect configuration drift across thousands of servers using Redfish. 10 hL
  3. D3Fleet out-of-band monitoringMonitor BMC health (temps, fans, PSUs, SEL) across a fleet, and separate cooling problems from workload problems. 12 hL
  4. E4Design a 512-GPU fabric on paperDesign the network for 64 nodes x 8 GPUs: rail-optimized leaf-spine, cable counts, oversubscription, congestion control. 12 hL
  5. F4Find the bad node by bisectionFind one slow node among hundreds without testing every pair. Build it as a simulation first, then run it for real under Slurm. Core12 hL
  6. G4Slurm on Kubernetes decision memo (Slinky, Soperator, Kueue)Customers ask 'Slurm or Kubernetes?'. Try Slinky on kind and write a decision memo. 10 hL
  7. H6Node health automation: cordon, drain, reset, rebootAutomatic detection-to-remediation for GPU faults on Kubernetes, without draining the whole cluster by mistake. 12 hG1
  8. H7Write a small operator with KubebuilderOperators run all GPU infra on K8s (GPU Operator, Network Operator, Slinky). Build one: GPUNodeAudit runs a diagnostic Job per matching node. 14 hL
  9. H8Security policy pack for a GPU platformAdmission policies, runtime detection and image scanning for a shared GPU cluster - your DevSecOps background applied to GPUs. 10 hL
  10. I2Land 1,024 GPUs: capacity, placement and rollout planThe SA job in one document: take a customer from 'we bought 1,024 GPUs' to production in waves. 10 hL
  11. I3Storage for model load and checkpointsModel load time and checkpoint stalls are infra problems. Measure storage tiers and recommend a design. 12 hG4
  12. J2Fleet reliability analyticsTurn failure data into decisions: find a bad batch, a bad rack, a bad driver. 12 hL
  13. J3Executive communication drillsThe JD stresses executive status, risks and decisions. Practice the formats. Core6 hL
