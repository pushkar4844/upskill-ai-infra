Boot OpenBMC in QEMU and talk to it two ways

See a BMC from the inside: boot real OpenBMC firmware in an emulator, query it with Redfish and IPMI.

Why it matters

Out-of-band debugging during early-stage bring-up.

Gives evidence for these requirements in the posting:

  • Linux tools: dmesg, journalctl, lspci, numactl, ethtool, iostat, perf, nvidia-smi, ipmitool
  • BMC, IPMI, Redfish, out-of-band debugging

New to bmc and out-of-band? Read the 5-minute primer first.

What done looks like

Deliverable. Comparison table and a screen recording or transcript.
The outcome, step by step (field manual version)
  1. Build an OpenBMC image for a QEMU target following the OpenBMC README, and boot it with the QEMU fork.
  2. Reach its Redfish service (bmcweb) from the host with curl.
  3. If IPMI is enabled in your image, run ipmitool for sdr, sel list, chassis status, power status.
  4. Table the same facts as seen through IPMI and Redfish.

Hands-on steps

  1. Building OpenBMC needs ~100 GB disk and hours of CPU. Use a big spot VM (e.g. c6i.8xlarge, 200 GB gp3) via a copy of infra/vms with count=1, or a strong Linux PC. Install Yocto build deps (OpenBMC README lists them).
    sudo apt install -y git build-essential chrpath cpio diffstat gawk lz4 zstd python3 python3-distutils file wget qemu-system-arm
  2. Build an image for an emulated machine (romulus is the long-standing QEMU target; check the README for current targets).
    git clone https://github.com/openbmc/openbmc && cd openbmc
. setup romulus
bitbake obmc-phosphor-image      # hours; run inside tmux
  3. Boot it in QEMU with port forwards for SSH, HTTPS (Redfish) and IPMI.
    IMG=$(ls tmp/deploy/images/romulus/obmc-phosphor-image-romulus*.static.mtd | head -1)
qemu-system-arm -m 256 -M romulus-bmc -nographic \
  -drive file=$IMG,format=raw,if=mtd \
  -net nic -net user,hostfwd=:127.0.0.1:2222-:22,hostfwd=:127.0.0.1:2443-:443,hostfwd=udp:127.0.0.1:2623-:623,hostname=qemu
  4. From another terminal, Redfish and IPMI (OpenBMC's documented default dev credentials: root / 0penBmc).
    curl -k -u root:0penBmc https://127.0.0.1:2443/redfish/v1 | jq .
curl -k -u root:0penBmc https://127.0.0.1:2443/redfish/v1/Managers/bmc | jq .
sudo apt install -y ipmitool
ipmitool -I lanplus -H 127.0.0.1 -p 2623 -U root -P 0penBmc mc info
ipmitool -I lanplus -H 127.0.0.1 -p 2623 -U root -P 0penBmc sdr
ipmitool -I lanplus -H 127.0.0.1 -p 2623 -U root -P 0penBmc sel list
ipmitool -I lanplus -H 127.0.0.1 -p 2623 -U root -P 0penBmc chassis status
python3 ~/gpu-lab/bmc/redfish_health.py https://127.0.0.1:2443 root 0penBmc
  5. Table the same facts via IPMI and Redfish.
You should see. BMC console boots to a login prompt; Redfish service root returns JSON; ipmitool mc info answers.

Interview

Be ready for: What does a BMC do when the host OS is hung?

Show the answer you can now give

The BMC is a separate small computer on the board with its own network. When the host OS hangs, it still reports sensors and logs and can power-cycle the host, give a serial console and update firmware.

Go deeper

Hidden gem. Almost nobody on the candidate side has seen a BMC from the inside. Booting one is a cheap way to stand out.
