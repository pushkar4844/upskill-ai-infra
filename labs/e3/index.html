InfiniBand diagnostics cheat sheet (study task)

InfiniBand can't be emulated cheaply. Learn the tools and counters well enough to read real output, then confirm on borrowed hardware.

Why it matters

High-performance networking technologies and interconnects.

Gives evidence for these requirements in the posting:

  • RDMA, congestion control, high-bandwidth interconnects

New to rdma and interconnect? Read the 5-minute primer first.

What done looks like

Deliverable. One-page IB link-health cheat sheet. State plainly which entries you have not yet seen on hardware.
The outcome, step by step (field manual version)
  1. Read the UFM diagnostic utilities page. List ibstat, iblinkinfo, ibnetdiscover, perfquery, ibdiagnet and what each shows.
  2. For perfquery counters build a table of symbol errors, link-downed, receive errors and transmit discards with likely cause and action.
  3. Read how the subnet manager works through the OpenSM source tree and README.
  4. You cannot build a free IB lab. Check whether NVIDIA LaunchPad, a partner lab or a colleague's cluster is available, and annotate real command output when you get access.

Hands-on steps

  1. Read NVIDIA UFM 'InfiniBand diagnostic utilities' (Go deeper). Table: ibstat, ibstatus, iblinkinfo, ibnetdiscover, perfquery, ibdiagnet, ibping - what each shows, when to use it.
  2. Counter table from perfquery: SymbolErrorCounter, LinkErrorRecoveryCounter, LinkDownedCounter, PortRcvErrors, PortXmitDiscards, PortXmitWait - likely cause and action for each.
  3. Skim opensm source/README: what the subnet manager does (LIDs, routing tables) and why one must be running.
    git clone https://github.com/linux-rdma/opensm && less opensm/README
  4. If you get time on an IB cluster (LaunchPad, colleague), run each tool and paste real output into the sheet.
    ibstat
iblinkinfo | head
perfquery -x
sudo ibdiagnet
You should see. A one-page cheat sheet; entries you haven't seen on hardware clearly marked.

Interview

Be ready for: A link has a rising symbol error counter. What do you do before you replace the cable?

Show the answer you can now give

Rising symbol errors: check the counter rate after clearing, look at both ends, reseat/clean the cable, check the transceiver temperature/power, swap ports to see if the error follows the cable or the port, then replace.
