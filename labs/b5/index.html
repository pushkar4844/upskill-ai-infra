Why it matters

Lead end-to-end bring-up for hyperscaler customers; deliver executive-level status.

Gives evidence for these requirements in the posting:

  • Bring-up and validation of multi-GPU and multi-node NVIDIA platforms
  • Stand-out: pilot to high-volume deployment record

New to gpu health and diagnostics? Read the 5-minute primer first.

What done looks like

Deliverable. Runbook, criteria file and a sample report. This is your strongest interview artifact.
The outcome, step by step (field manual version)
  1. Define stages in order: inventory, DCGM r3, gpu-burn, single-node NCCL over NVLink, nvbandwidth, ibping and ib_*_bw, multi-node all-reduce scaling, storage with fio, a reference training run, telemetry.
  2. Put every threshold in one criteria file. Together's guide uses about 92% of theoretical fabric bandwidth as the multi-node all-reduce bar, for example 370 GB/s on a 400 GB/s fabric. Justify your own numbers.
  3. Scale tests as groups: single node, pairs, racks, full cluster, so a failure points at a node, leaf or spine.
  4. Run NVIDIA's Cluster Readiness Engine on a Kubernetes cluster and compare its report with your hand-built one.
  5. Produce a report: pass/fail table, defect log, owner, disposition, and a go/no-go line.

Hands-on steps

  1. Define the stages in order: inventory -> DCGM r3 -> burn-in -> single-node NCCL -> nvbandwidth -> RDMA/EFA perftest -> multi-node all-reduce scaling -> storage fio -> reference training run -> telemetry check.
  2. Put every threshold in one criteria file, with a justification line each.
    cat > ~/gpu-lab/capstone/criteria.toml <<'EOF'
[inventory]
gpus_per_node = 4                 # g4dn.12xlarge; 8 on HGX
driver = "<expected version>"
[dcgm]
level = 3
allow_fail = []
[burnin]
minutes = 30
max_temp_c = 85
max_uncorrected_ecc = 0
clock_band_pct = 5                # SM clock within 5% of node median
[nccl_single_node]
min_busbw_gbps_at_1g = 0          # set from your F1 baseline
[nccl_multi_node]
fraction_of_theoretical = 0.92   # Together AI guide's bar; justify yours
theoretical_gbps = 0             # fill from fabric spec
[storage]
min_seq_read_gbps = 0
[go_no_go]
require_all = true
EOF
  3. Scale tests as groups: single node -> pairs -> rack -> full cluster, so a failure points at a node, leaf or spine.
  4. Write a runner (bash or Python) that executes each stage, saves raw output under reports/<date>/ and compares to criteria. Reuse your scripts: triage.sh, dcgm_report.py, gpu-burn logging, nccl-tests, pcie_check.sh.
    mkdir -p ~/gpu-lab/capstone/{stages,reports}
# stages/10_inventory.sh 20_dcgm.sh 30_burnin.sh 40_nccl_node.sh 50_rdma.sh 60_nccl_multi.sh 70_storage.sh
# run_acceptance.py reads criteria.toml, runs stages, writes reports/<date>/summary.md with PASS/FAIL per stage
  5. Optional: run NVIDIA's Cluster Readiness Engine on a K8s cluster and compare its report with yours.
  6. Produce a sample report: pass/fail table, defect log (owner, disposition), go/no-go line.
You should see. One command produces a dated report folder with raw outputs and a summary with a clear go/no-go.

Interview

Be ready for: How do you validate a new 256-GPU cluster before handing it to the customer?

Show the answer you can now give

New 256-GPU cluster: inventory and firmware/driver baseline, DCGM r3 and burn-in per node, single-node NCCL over NVLink, NIC/RDMA tests, then all-reduce at pair, rack and full scale against a threshold like ~92% of fabric bandwidth, storage and a reference training run - with a signed report and defect log.

Go deeper

Hidden gem. NVCRE's Diagnose scale reruns failing groups with smaller membership until it isolates suspects. Copy that idea in your own tooling.
