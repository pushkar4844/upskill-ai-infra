Why it matters

Hardware health monitoring and out-of-band debugging; analyze product health trends.

Gives evidence for these requirements in the posting:

  • BMC, IPMI, Redfish, out-of-band debugging

New to bmc and out-of-band? Read the 5-minute primer first.

What done looks like

Deliverable. Dashboard JSON, alert rules and one OCP-format result file.
The outcome, step by step (field manual version)
  1. Point a Redfish exporter at your mockup or real BMCs and scrape it with Prometheus.
  2. Build Grafana panels: inlet temperature, fan speed, PSU redundancy, SEL critical entries.
  3. Write alert rules for loss of PSU redundancy and rising inlet temperature across a rack.
  4. Emit one diagnostic result in the OCP diagnostic output format using the Python library.
  5. Join BMC temperatures with GPU temperatures from DCGM to separate a cooling problem from a workload problem.

Hands-on steps

  1. Run 3 mockup containers on ports 8001-8003 to pretend you have 3 servers.
    for p in 8001 8002 8003; do docker run -d --name rf$p -p $p:8000 dmtf/redfish-mockup-server:latest; done
  2. Run a Redfish exporter (jenningsloy318/redfish_exporter - build/run per README) pointing at the 3 mockups; scrape with Prometheus (reuse J1 compose locally).
  3. Grafana panels: inlet temp, fan speed, PSU redundancy, SEL critical entries. Alert rules: PSU redundancy lost, inlet temp rising across a rack.
  4. Emit one diagnostic result in OCP diagnostic format with ocp-diag-core-python (README example).
    pip install ocptv   # package name per the repo README
  5. Write how you'd join BMC inlet temps with DCGM GPU temps to separate cooling from workload.
You should see. Dashboard showing 3 'servers', alert rules, an OCP-format JSON result.

Interview

Be ready for: Rack 14 has hot GPUs. How do you prove it is cooling and not workload?

Show the answer you can now give

Rack 14 hot GPUs: compare BMC inlet temps and fan speeds across the rack with GPU temps and power from DCGM. Inlet high for all nodes = cooling; inlet normal but GPU hot at the same power = that GPU/heatsink; high power = workload.

Go deeper

Hidden gem. OCP's diagnostic schema is what hyperscaler hardware teams use to standardize test output. Knowing it signals you have worked near the data center side.
