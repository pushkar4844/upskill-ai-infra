Why it matters

Kubernetes security depth that interviewers probe, and your DevSecOps background gives you an edge.

New to kubernetes for gpus? Read the 5-minute primer first.

What done looks like

Deliverable. A policy repository with tests and a one-page threat model.
The outcome, step by step (field manual version)
  1. Write admission policies in Kyverno or Gatekeeper: block privileged pods outside the operator namespace, require GPU limits on pods that request nvidia.com/gpu, deny hostPath mounts of /dev.
  2. Add a Falco rule that alerts when an unexpected process opens /dev/nvidia*.
  3. Scan CUDA base images with Trivy and set a policy on severity.
  4. Read the confidential-computing tooling repo and write down which threat it addresses.

Hands-on steps

  1. Install Kyverno on kind.
    helm repo add kyverno https://kyverno.github.io/kyverno/ && helm install kyverno kyverno/kyverno -n kyverno --create-namespace
  2. Policy 1: pods requesting nvidia.com/gpu must set limits; Policy 2: no privileged pods outside gpu-operator ns; Policy 3: no hostPath to /dev.
    cat > require-gpu-limits.yaml <<'EOF'
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata: { name: require-gpu-limits }
spec:
  validationFailureAction: Enforce
  rules:
  - name: gpu-limits
    match: { any: [ { resources: { kinds: [Pod] } } ] }
    preconditions:
      any:
      - key: "{{ request.object.spec.containers[].resources.requests.\"nvidia.com/gpu\" || '' }}"
        operator: NotEquals
        value: ""
    validate:
      message: "Pods requesting GPUs must set nvidia.com/gpu limits"
      pattern:
        spec:
          containers:
          - resources: { limits: { nvidia.com/gpu: "?*" } }
EOF
kubectl apply -f require-gpu-limits.yaml
# write the other two from Kyverno's policy library (disallow-privileged, disallow-host-path)
  3. Test with good and bad pods; write Kyverno CLI tests (kyverno test).
  4. Falco rule idea: alert when an unexpected process opens /dev/nvidia*; Trivy scan of a CUDA base image with a severity gate.
    docker run --rm aquasec/trivy image --severity HIGH,CRITICAL nvcr.io/nvidia/cuda:12.4.1-base-ubuntu22.04
  5. Threat model page: multi-tenant GPU risks (privileged escape, device access, driver CVEs, memory remnants between tenants -> MIG / confidential computing via nvtrust).
You should see. Bad pods rejected with clear messages; Trivy report; threat model.
