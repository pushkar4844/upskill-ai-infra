Build an XID decoder

XID errors are how the NVIDIA driver reports GPU problems in the kernel log. You will build a tool that reads them and tells an operator what to do. No GPU needed.

L Laptop (Windows + WSL2 Ubuntu)
Time
5 hours

Why it matters

Solve problems involving GPUs, drivers, firmware and distributed system interactions.

New to gpu health and diagnostics? Read the 5-minute primer first.

What done looks like

Deliverable. xidwatch.py with tests and the classification table.
The outcome, step by step (field manual version)
  1. Read the XID catalog and tabulate these codes with meaning and action: 13, 31, 43, 45, 48, 62, 63, 64, 74, 79, 92, 94, 95, 119, 120.
  2. Sort them into application-level (13, 31, 43), memory (48, 63, 64, 92, 94, 95), interconnect (74), bus (79) and firmware (119, 120).
  3. Write xidwatch.py that follows journalctl -k -f for NVRM: Xid, maps each line to the table and prints severity plus recommended action.
  4. Unit-test it with sample lines you write from the catalog format. No GPU needed.

Hands-on steps

  1. Open the NVIDIA XID catalog (link in Go deeper). Fill this starter table. Meanings below are the common ones - confirm each 'action' against the catalog before you trust it.
    mkdir -p ~/gpu-lab/gpu-health && cd ~/gpu-lab/gpu-health
cat > xid_table.json <<'EOF'
{
 "13": {"name": "Graphics engine exception", "cat": "application", "sev": "low",  "action": "Usually app bug; check the job. Repeats on one GPU -> run DCGM diag"},
 "31": {"name": "GPU memory page fault",     "cat": "application", "sev": "low",  "action": "Illegal memory access by app; check app/driver"},
 "43": {"name": "GPU stopped processing",    "cat": "application", "sev": "low",  "action": "App-level; restart job"},
 "45": {"name": "Preemptive cleanup",        "cat": "application", "sev": "info", "action": "Follows a killed process; read the earlier XID"},
 "48": {"name": "Double-bit ECC error",      "cat": "memory",      "sev": "high", "action": "Uncorrectable; drain, reset GPU, check retired/remapped rows"},
 "62": {"name": "Internal micro-controller halt", "cat": "firmware", "sev": "high", "action": "Reset GPU; repeated -> RMA"},
 "63": {"name": "Row remapping event",       "cat": "memory",      "sev": "info", "action": "Recorded; reset GPU at next drain to apply"},
 "64": {"name": "Row remapping failure",     "cat": "memory",      "sev": "high", "action": "Drain, reset; persistent -> RMA"},
 "74": {"name": "NVLink error",              "cat": "interconnect","sev": "high", "action": "Check NVLink counters/fabric manager; reset; persistent -> hardware"},
 "79": {"name": "GPU has fallen off the bus","cat": "bus",         "sev": "critical", "action": "Drain node, reboot host, check PCIe/power; escalate to vendor"},
 "92": {"name": "High single-bit ECC rate",  "cat": "memory",      "sev": "medium","action": "Watch trend; schedule diag"},
 "94": {"name": "Contained ECC error",       "cat": "memory",      "sev": "medium","action": "App killed, GPU OK; reset at drain"},
 "95": {"name": "Uncontained ECC error",     "cat": "memory",      "sev": "high", "action": "Drain and reset GPU"},
 "119":{"name": "GSP RPC timeout",           "cat": "firmware",    "sev": "high", "action": "Reset GPU / reboot; check driver version"},
 "120":{"name": "GSP error",                 "cat": "firmware",    "sev": "high", "action": "Reset GPU / reboot; check driver version"}
}
EOF
  2. Write xidwatch.py. It reads kernel log lines from stdin (or a file), finds 'NVRM: Xid', and prints severity + action.
    cat > xidwatch.py <<'EOF'
#!/usr/bin/env python3
"""Decode NVIDIA XID lines. Usage: journalctl -k -f | ./xidwatch.py   or   ./xidwatch.py < sample.log"""
import json, re, sys, pathlib
TABLE = json.loads((pathlib.Path(__file__).parent / "xid_table.json").read_text())
PAT = re.compile(r"NVRM: Xid \(PCI:(?P<bdf>[0-9a-fA-F:.]+)\): (?P<xid>\d+),?(?P<rest>.*)")

def decode(line):
    m = PAT.search(line)
    if not m:
        return None
    xid = m.group("xid")
    info = TABLE.get(xid, {"name": "unknown XID", "cat": "unknown", "sev": "check", "action": "Look up in NVIDIA XID catalog"})
    return {"bdf": m.group("bdf"), "xid": int(xid), **info, "detail": m.group("rest").strip()}

if __name__ == "__main__":
    for line in sys.stdin:
        d = decode(line)
        if d:
            print(f"[{d['sev'].upper():8}] GPU {d['bdf']} XID {d['xid']} {d['name']} ({d['cat']}) -> {d['action']}", flush=True)
EOF
chmod +x xidwatch.py
  3. Make sample log lines in the same shape the driver writes and test.
    cat > sample.log <<'EOF'
Oct 10 10:01:02 node7 kernel: NVRM: Xid (PCI:0000:3b:00): 79, pid=0, GPU has fallen off the bus.
Oct 10 10:02:11 node7 kernel: NVRM: Xid (PCI:0000:5e:00): 48, pid=1234, An uncorrectable double bit error
Oct 10 10:02:12 node7 kernel: NVRM: Xid (PCI:0000:5e:00): 63, pid=1234, Row remapping event
Oct 10 10:03:00 node7 kernel: eth0: link up
EOF
./xidwatch.py < sample.log
  4. Add unit tests with pytest.
    python3 -m venv .venv && . .venv/bin/activate && pip install pytest
cat > test_xidwatch.py <<'EOF'
from xidwatch import decode
def test_79():
    d = decode("kernel: NVRM: Xid (PCI:0000:3b:00): 79, pid=0, GPU has fallen off the bus.")
    assert d["xid"] == 79 and d["sev"] == "critical" and d["bdf"] == "0000:3b:00"
def test_non_xid():
    assert decode("eth0: link up") is None
def test_unknown():
    assert decode("NVRM: Xid (PCI:0000:01:00): 999, x")["cat"] == "unknown"
EOF
pytest -q
  5. Later, on a GPU instance (S8), run it live.
    journalctl -k -f | ~/gpu-lab/gpu-health/xidwatch.py
You should see. ./xidwatch.py < sample.log prints 3 lines: CRITICAL for 79, HIGH for 48, INFO for 63, and ignores the eth0 line. pytest: 3 passed.

Interview

Be ready for: Xid 79 appears in dmesg. What does it mean and what do you do? How does it differ from Xid 48 followed by 63 or 64?

Show the answer you can now give

XID 79 means the GPU dropped off PCIe - drain and reboot, check power/PCIe, escalate. 48 is an uncorrectable ECC error; 63 is a row-remap event that applies at next reset; 64 means the remap failed. I built a decoder that turns those log lines into actions.
