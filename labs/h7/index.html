Write a small operator with Kubebuilder

Operators run all GPU infra on K8s (GPU Operator, Network Operator, Slinky). Build one: GPUNodeAudit runs a diagnostic Job per matching node.

Why it matters

Practical Kubernetes depth: CRDs and operators are central to the GPU Operator, Network Operator and Slinky.

New to kubernetes for gpus? Read the 5-minute primer first.

What done looks like

Deliverable. A repository with CRD, controller, tests and a README.
The outcome, step by step (field manual version)
  1. Scaffold a project with Kubebuilder and define a GPUNodeAudit CRD with spec (node selector, diagnostic level) and status (result, time).
  2. Reconcile by creating a Job per matching node that runs a diagnostic and writes the result back.
  3. Add RBAC, finalizers and status conditions. Test with envtest.
  4. Read the GPU Operator's controller structure and write down three design patterns you borrowed.

Hands-on steps

  1. Install Go and kubebuilder (see the Kubebuilder book quick start).
    sudo snap install go --classic   # or download from go.dev
curl -L -o kubebuilder "https://go.kubebuilder.io/dl/latest/$(go env GOOS)/$(go env GOARCH)" && chmod +x kubebuilder && sudo mv kubebuilder /usr/local/bin/
  2. Scaffold.
    mkdir -p ~/gpu-lab/k8s/gpu-audit && cd ~/gpu-lab/k8s/gpu-audit
kubebuilder init --domain lab.io --repo github.com/<you>/gpu-audit
kubebuilder create api --group ops --version v1alpha1 --kind GPUNodeAudit --resource --controller
  3. Spec: nodeSelector, diagLevel. Status: per-node result, lastRun, conditions. Reconcile: list matching nodes, create one Job per node (nodeName set) running a diagnostic command, read Job status, write results to status. Make it idempotent (deterministic Job names, owner references).
  4. Run against kind with KWOK fake nodes from H4 (Jobs run as busybox 'echo PASS').
    make install && make run
kubectl apply -f config/samples/
  5. Add envtest unit tests (make test). Read gpu-operator's controllers and write 3 patterns you borrowed.
You should see. Applying a GPUNodeAudit creates one Job per matching node and the status shows per-node PASS.

Interview

Be ready for: Describe a reconcile loop and how you make it idempotent.

Show the answer you can now give

A reconcile loop reads desired state (spec) and actual state, makes one step toward desired, writes status and requeues. Idempotent = deterministic names, create-if-absent, owner references, safe to run any number of times.
