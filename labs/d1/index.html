Redfish 101 on a mockup server

Redfish is the REST API every modern server BMC exposes (power, temps, fans, logs, firmware). You'll learn it with no hardware using DMTF's mockup server.

Why it matters

BMC, IPMI and Redfish for remote management, health monitoring and out-of-band debugging.

Gives evidence for these requirements in the posting:

  • BMC, IPMI, Redfish, out-of-band debugging

New to bmc and out-of-band? Read the 5-minute primer first.

What done looks like

Deliverable. redfish_health.py and the validator output.
The outcome, step by step (field manual version)
  1. Start the Redfish Mockup Server with a sample mockup directory (see its README for flags).
  2. Walk /redfish/v1: Systems, Chassis (thermal, power), Managers, LogServices (the SEL), UpdateService.
  3. Write Python with the DMTF client that prints temperatures, fan states, PSU status and the last ten log entries.
  4. Run the Redfish Service Validator against the mockup and read what it reports.

Hands-on steps

  1. Run the mockup server. Easiest path is the published container (it ships a sample server); if the image name/tag changed, follow the repo README to run redfishMockupServer.py with -D <mockup dir> instead.
    docker run -d --name rf -p 8000:8000 dmtf/redfish-mockup-server:latest
curl -s localhost:8000/redfish/v1 | jq .
  2. Walk the tree by hand. Follow every @odata.id link.
    curl -s localhost:8000/redfish/v1/Systems | jq .
SYS=$(curl -s localhost:8000/redfish/v1/Systems | jq -r '.Members[0]."@odata.id"')
curl -s localhost:8000$SYS | jq '{PowerState, Status, ProcessorSummary, MemorySummary}'
curl -s localhost:8000/redfish/v1/Chassis | jq .
CH=$(curl -s localhost:8000/redfish/v1/Chassis | jq -r '.Members[0]."@odata.id"')
curl -s localhost:8000$CH/Thermal | jq '.Temperatures[] | {Name, ReadingCelsius}'
curl -s localhost:8000$CH/Power   | jq '.PowerSupplies[] | {Name, Status}'
curl -s localhost:8000/redfish/v1/Managers | jq .
curl -s localhost:8000$SYS/Bios | jq '.Attributes'    # if present in the mockup
  3. Write redfish_health.py.
    mkdir -p ~/gpu-lab/bmc && cd ~/gpu-lab/bmc && python3 -m venv .venv && . .venv/bin/activate && pip install requests
cat > redfish_health.py <<'EOF'
#!/usr/bin/env python3
"""Print health of every chassis/system on a Redfish endpoint. Usage: redfish_health.py http://localhost:8000 [user pass]"""
import sys, requests
base = sys.argv[1].rstrip('/'); auth = tuple(sys.argv[2:4]) or None
s = requests.Session(); s.verify = False; s.auth = auth
get = lambda p: s.get(base + p, timeout=10).json()
for m in get('/redfish/v1/Systems')['Members']:
    sysd = get(m['@odata.id'])
    print(f"SYSTEM {sysd.get('Id')} power={sysd.get('PowerState')} health={sysd.get('Status',{}).get('Health')}")
for m in get('/redfish/v1/Chassis')['Members']:
    ch = get(m['@odata.id']); cid = ch['@odata.id']
    try:
        th = get(cid + '/Thermal')
        for t in th.get('Temperatures', []):
            print(f"  TEMP {t.get('Name'):30} {t.get('ReadingCelsius')} C  {t.get('Status',{}).get('Health')}")
        for f in th.get('Fans', []):
            print(f"  FAN  {f.get('Name') or f.get('FanName'):30} {f.get('Reading')} {f.get('ReadingUnits','')}")
        pw = get(cid + '/Power')
        for p in pw.get('PowerSupplies', []):
            print(f"  PSU  {p.get('Name'):30} {p.get('Status',{}).get('Health')}")
    except Exception as e:
        print('  (no Thermal/Power on', cid, '-', e, ')')
EOF
python3 redfish_health.py http://localhost:8000
  4. Run DMTF's Service Validator against the mockup and read the report. Check its README/--help for the exact address flag of your version.
    git clone https://github.com/DMTF/Redfish-Service-Validator && cd Redfish-Service-Validator
pip install -r requirements.txt
python3 RedfishServiceValidator.py --help | head -30
python3 RedfishServiceValidator.py --ip http://localhost:8000   # flag name per --help
  5. Read the IPMI vs Redfish comparison in the DMTF docs (Go deeper) and write 5 bullets.
You should see. redfish_health.py prints the system with PowerState, temperatures with readings, fans and PSUs with Health OK. The validator writes an HTML report with pass/warn counts.

Interview

Be ready for: IPMI versus Redfish: what changed and why do hyperscalers prefer Redfish?

Show the answer you can now give

IPMI is an old binary protocol with weak security and vendor quirks; Redfish is HTTPS + JSON with a schema, sessions and eventing, so hyperscalers automate fleets with it - inventory, power, thermal, logs and firmware updates from one API.
