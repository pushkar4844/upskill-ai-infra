Draw the node from memory

Know which GPU sits next to which CPU socket and NIC. Every performance discussion (NUMA, GPUDirect, NCCL) starts from this picture.

Where
G4 One multi-GPU node (g4dn.12xlarge 4xT4 or g5.12xlarge 4xA10G)
Time
5 hours
Cost
~$2 (1 h of g4dn.12xlarge spot)
Do first
S8 with instance_type = g4dn.12xlarge (or any multi-GPU node)

Why it matters

PCIe topologies, NUMA, memory subsystem behavior.

Gives evidence for these requirements in the posting:

  • Linux tools: dmesg, journalctl, lspci, numactl, ethtool, iostat, perf, nvidia-smi, ipmitool
  • Server hardware: PCIe, firmware, NUMA, BIOS/UEFI, power and thermal

New to server hardware and topology? Read the 5-minute primer first.

What done looks like

Deliverable. Topology diagram and the three binding rules.
The outcome, step by step (field manual version)
  1. Collect: nvidia-smi topo -m, lspci -tv, lstopo, numactl -H, lscpu, and /sys/class/net/*/device/numa_node.
  2. Decode the topology legend: X, SYS, NODE, PHB, PXB, PIX, NV#. Note which pairs cross sockets.
  3. Map each GPU to its closest NIC and CPU socket. Mark which GPU-NIC pairs sit under the same PCIe switch.
  4. Draw the diagram and write three rules, for example 'bind rank N to NUMA node M and NIC K'.

Hands-on steps

  1. Bring up the node and log in.
    cd ~/gpu-lab/infra/gpu1 && terraform apply -var instance_type=g4dn.12xlarge
aws ssm start-session --target $(terraform output -raw id)
sudo -iu ubuntu && sudo apt install -y hwloc numactl pciutils
  2. Collect the topology facts into one file.
    mkdir -p ~/topo && cd ~/topo
{ nvidia-smi topo -m; echo; numactl -H; echo; lscpu; echo; lspci -tv; } > topo.txt 2>&1
for n in /sys/class/net/*/device/numa_node; do echo "$n $(cat $n)"; done >> topo.txt
nvidia-smi --query-gpu=index,pci.bus_id,name --format=csv >> topo.txt
lstopo-no-graphics --of txt > lstopo.txt
cat topo.txt
  3. Decode the nvidia-smi topo legend: X = self, PIX = same PCIe switch, PXB = multiple PCIe switches, PHB = same host bridge, NODE = same NUMA node across host bridges, SYS = crosses sockets (slowest), NV# = NVLink with # links. Write which GPU pairs are what.
  4. Copy the files back to your laptop (SSM has no scp; simplest: print and paste, or push to an S3 bucket you own).
    aws s3 cp ~/topo s3://<your-lab-bucket>/topo/ --recursive   # needs s3 permission on the role; or just cat and copy
  5. Draw it (draw.io or Excalidraw): sockets, NUMA nodes, PCIe switches, GPUs, NICs. Write 3 rules, e.g. 'rank on GPU0 binds to NUMA 0 and NIC X'. Compare with the DGX/HGX H100 diagram from the SuperPOD docs (Go deeper) - learn that picture too.
  6. Destroy.
    exit; exit
terraform destroy -auto-approve
You should see. On g4dn/g5 you'll see PHB/NODE/SYS between GPUs (no NV#) - that's the point: no NVLink, all GPU-GPU traffic over PCIe. Single-socket sizes show 1 NUMA node.

Interview

Be ready for: Draw an 8-GPU HGX node: GPUs, NVSwitches, NICs, CPUs. Where does GPUDirect RDMA traffic flow?

Show the answer you can now give

On an HGX H100 node 8 GPUs connect through NVSwitch, each GPU pairs with a NIC under the same PCIe switch, split across two CPU sockets. GPUDirect RDMA traffic goes GPU->PCIe switch->NIC without touching CPU memory, so placement under the same switch matters.
