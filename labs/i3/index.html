Storage for model load and checkpoints

Model load time and checkpoint stalls are infra problems. Measure storage tiers and recommend a design.

Why it matters

System bottleneck analysis; the mentoring call stressed storage tiers for model weights.

Gives evidence for these requirements in the posting:

  • Find bottlenecks at cluster, node, accelerator, network, application layers

New to cloud, capacity and storage? Read the 5-minute primer first.

What done looks like

Deliverable. Results table and the tiering recommendation.
The outcome, step by step (field manual version)
  1. Run a fio matrix (sequential and random, read and write, several block sizes) on local NVMe, a parallel file system and an object-store mount.
  2. Time loading a model checkpoint from each source and from a streaming loader.
  3. Measure checkpoint write bandwidth and compute the training stall per save at your checkpoint interval.
  4. Run the MLPerf Storage benchmark if you have the budget, or read its rules and results.
  5. Recommend a tiering design: object store, cache, local NVMe, parallel FS.

Hands-on steps

  1. fio matrix on local NVMe (g4dn has instance store), EBS gp3, and an S3 mount (Mountpoint for S3).
    sudo apt install -y fio
# instance store: lsblk; sudo mkfs.xfs /dev/nvme1n1; sudo mount /dev/nvme1n1 /mnt/nvme
for rw in read write randread; do for bs in 4k 1M; do
 fio --name=$rw-$bs --rw=$rw --bs=$bs --size=4G --numjobs=4 --iodepth=32 --ioengine=libaio --direct=1 --runtime=30 --time_based --directory=/mnt/nvme --group_reporting | grep -E 'IOPS|BW'
done; done
# Mountpoint: install per awslabs/mountpoint-s3 README, mount-s3 <bucket> /mnt/s3
  2. Time loading a model (e.g. a 7B safetensors checkpoint from Hugging Face) from each tier; try a streaming loader (CoreWeave tensorizer or Run:ai model streamer) if time.
  3. Checkpoint math: size / write bandwidth = stall per checkpoint; combine with K3 interval.
  4. Recommendation: object store as source of truth, local NVMe cache, parallel FS (FSx for Lustre) for shared high-throughput, async checkpoint to local then drain to object store.

Interview

Be ready for: A 70B model takes 12 minutes to load on each scale-out. How do you cut it?

Show the answer you can now give

70B model taking 12 min per scale-out: pre-stage weights on local NVMe or a node-local cache, stream with a parallel loader, use a parallel FS or high-throughput object access with many connections, and keep images slim so pull time doesn't add up.
