RDMA from zero on Soft-RoCE

RDMA lets one machine write into another's memory without the remote CPU. It's what InfiniBand/RoCE/EFA give NCCL. Soft-RoCE emulates it in software on any NIC, so you learn the commands and concepts for free.

Where
V Two small Linux VMs (AWS t3.large or VirtualBox)
Time

Understanding of RDMA, congestion control and high-bandwidth interconnects in distributed AI workloads.

What done looks like

Deliverable. Notes plus a results table. Numbers are meaningless in absolute terms; the commands and concepts are the point.
The outcome, step by step (field manual version)
  1. On an Ubuntu VM install rdma-core, the verbs utilities and perftest.
  2. Create a software RDMA device on the VM NIC: sudo rdma link add rxe0 type rxe netdev <nic>. Confirm with ibv_devices and ibv_devinfo.
  3. Run ib_write_bw as server and client across two VMs, then ib_send_lat. Sweep message sizes with -a.
  4. Compare against iperf3 over TCP on the same pair.
  5. Write one page explaining queue pairs, memory regions, protection domains and completion queues in your own words.

Hands-on steps

  1. Create the two VMs and open a session on each (two terminals).
    cd ~/gpu-lab/infra/vms && terraform init && terraform apply
terraform output
aws ssm start-session --target <id-0>     # terminal A
aws ssm start-session --target <id-1>     # terminal B
sudo -iu ubuntu
  2. On BOTH VMs: install RDMA user space + the kernel module package that contains rdma_rxe.
    sudo apt update
sudo apt install -y rdma-core ibverbs-utils perftest iperf3 linux-modules-extra-$(uname -r)
sudo modprobe rdma_rxe
ip -br link            # note the NIC name, e.g. ens5
sudo rdma link add rxe0 type rxe netdev ens5
rdma link
ibv_devices
ibv_devinfo -d rxe0    # state: PORT_ACTIVE
  3. Bandwidth test. A = server, B = client (use A's private IP from terraform output). If it can't connect, add -x 1 (RoCEv2 GID index) on both sides.
    # A
ib_write_bw -d rxe0
# B
ib_write_bw -d rxe0 <A_private_ip>
  4. Latency test and size sweep.
    # A
ib_send_lat -d rxe0
# B
ib_send_lat -d rxe0 <A_private_ip>
# sweep all message sizes
# A: ib_write_bw -d rxe0 -a     B: ib_write_bw -d rxe0 -a <A_private_ip>
  5. TCP baseline on the same pair.
    # A
iperf3 -s
# B
iperf3 -c <A_private_ip> -t 20
  6. Write one page in your own words: queue pair (QP), memory region (MR), protection domain (PD), completion queue (CQ), and why RDMA saves CPU and copies.
  7. Destroy.
    terraform destroy -auto-approve
You should see. ibv_devinfo shows rxe0 PORT_ACTIVE. ib_write_bw prints a bandwidth table (Soft-RoCE is CPU-bound, so numbers can be lower than iperf3 - that is fine and worth explaining).

If it breaks

SymptomFix
modprobe: FATAL: Module rdma_rxe not foundInstall linux-modules-extra-$(uname -r); if your kernel flavor lacks it, use the generic kernel or a VirtualBox Ubuntu VM
Couldn't connect to <ip>:18515Security group must allow all traffic between the VMs (S7 does); perftest uses TCP 18515 for setup and UDP 4791 for RoCEv2
Failed to modify QP to RTRAdd -x 1 (GID index for RoCEv2) on both sides; check 'show_gids'

Interview

Be ready for: Explain RDMA to a cloud engineer in 60 seconds. Why does it matter for all-reduce?

Show the answer you can now give

RDMA moves data NIC-to-memory without the remote CPU or kernel copies, using queue pairs and registered memory regions. All-reduce sends huge buffers between GPUs every step, so the fabric must be RDMA (IB, RoCE or EFA) or the GPUs sit idle.

Go deeper

Hidden gem. Soft-RoCE gives you a free RDMA lab on any Linux VM. Most RDMA tutorials assume you own ConnectX cards.
