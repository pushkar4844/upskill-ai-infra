nccl-tests on one node and the busbw formula

NCCL is the library that moves data between GPUs for training. nccl-tests measures it. Learn to run it, read algbw vs busbw, and plot results.

Where
G4 One multi-GPU node (g4dn.12xlarge 4xT4 or g5.12xlarge 4xA10G)
Time
6 hours
Cost
~$3-5
Do first
S8 (g4dn.12xlarge or g5.12xlarge), C1

Why it matters

NCCL, NVSwitch/NVLink and performance tuning.

Gives evidence for these requirements in the posting:

  • CUDA, NCCL, NVSwitch/NVLink, drivers, performance tuning

New to nccl and collectives? Read the 5-minute primer first.

What done looks like

Deliverable. Plots, CSVs and a table of the formulas with your own measurements.
The outcome, step by step (field manual version)
  1. Build nccl-tests and run all_reduce_perf -b 8 -e 8G -f 2 -g <num_gpus>.
  2. Derive busbw from algbw: for all-reduce multiply by 2(n-1)/n; for all-gather and reduce-scatter by (n-1)/n; broadcast uses a factor of 1.
  3. Compare busbw at large messages with the NVLink bandwidth your node should reach.
  4. Run all-gather, reduce-scatter and all-to-all. Toggle NCCL_ALGO between Ring and Tree and note when each wins.
  5. Save CSV and make a latency-versus-size and busbw-versus-size plot.

Hands-on steps

  1. Start a 4-GPU node.
    cd ~/gpu-lab/infra/gpu1 && terraform apply -var instance_type=g4dn.12xlarge
aws ssm start-session --target $(terraform output -raw id); sudo -iu ubuntu; nvidia-smi -L
  2. Find NCCL and build nccl-tests.
    find / -name 'libnccl.so*' 2>/dev/null | head     # note the folder, e.g. /usr/local/cuda/lib or /usr/lib/x86_64-linux-gnu
git clone https://github.com/NVIDIA/nccl-tests && cd nccl-tests
make -j CUDA_HOME=/usr/local/cuda NCCL_HOME=/usr        # NCCL_HOME = parent of the lib folder you found
ls build/
  3. Run all-reduce across the 4 GPUs.
    ./build/all_reduce_perf -b 8 -e 4G -f 2 -g 4 | tee ~/ar.txt
  4. Understand the columns: algbw = size / time. busbw = algbw x 2(n-1)/n for all-reduce (n = 4 -> x1.5). busbw is comparable to link bandwidth whatever n is. Check one row by hand.
  5. Run the other collectives and compare algorithms.
    ./build/all_gather_perf -b 8 -e 4G -f 2 -g 4 | tee ~/ag.txt
./build/reduce_scatter_perf -b 8 -e 4G -f 2 -g 4 | tee ~/rs.txt
./build/alltoall_perf -b 8 -e 1G -f 2 -g 4 | tee ~/a2a.txt
NCCL_ALGO=Ring ./build/all_reduce_perf -b 1M -e 1G -f 4 -g 4
NCCL_ALGO=Tree ./build/all_reduce_perf -b 1M -e 1G -f 4 -g 4
NCCL_DEBUG=INFO ./build/all_reduce_perf -b 1G -e 1G -g 4 2>&1 | grep -iE 'NCCL INFO (Channel|Ring|Tree|P2P|via)' | head
  6. Plot busbw vs size on your laptop (paste ar.txt into results/).
    cat > ~/gpu-lab/nccl/plot_nccl.py <<'EOF'
import sys, matplotlib.pyplot as plt
rows=[l.split() for l in open(sys.argv[1]) if l.strip() and l.strip()[0].isdigit()]
size=[int(r[0]) for r in rows]; busbw=[float(r[7]) for r in rows]   # out-of-place busbw column
plt.semilogx(size, busbw, marker='o'); plt.xlabel('bytes'); plt.ylabel('busbw GB/s'); plt.title(sys.argv[1]); plt.grid(True)
plt.savefig(sys.argv[1]+'.png', dpi=120); print('saved')
EOF
pip install matplotlib && python3 ~/gpu-lab/nccl/plot_nccl.py ~/gpu-lab/results/ar.txt
  7. Destroy.
    terraform destroy -auto-approve
You should see. busbw rises with message size and plateaus. On g4dn/g5 (PCIe, no NVLink) the plateau is in the low tens of GB/s or less; on an NVLink/NVSwitch H100 node it would be hundreds. 'Avg bus bandwidth' line at the end.

Check yourself

If it breaks

SymptomFix
nccl.h not found during makeSet NCCL_HOME to where include/nccl.h lives (find / -name nccl.h)
libnccl.so not found at run timeexport LD_LIBRARY_PATH=<nccl lib dir>:$LD_LIBRARY_PATH
Column index wrong in plotPrint one row and count columns; busbw is the 7th/8th field depending on version

Interview

Be ready for: What is the difference between algbw and busbw, and why does busbw exist?

Show the answer you can now give

algbw is bytes over time; busbw multiplies by 2(n-1)/n for all-reduce so it reflects per-link traffic and is comparable to hardware bandwidth regardless of GPU count. I compare large-message busbw to the NVLink or NIC line rate.
