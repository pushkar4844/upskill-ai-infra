The 60-second node triage drill

Learn the first commands you run on any slow node, and what each one rules out. You will create each bottleneck yourself, so you know what it looks like.

Time
5 hours

Why it matters

Proficiency with dmesg, journalctl, lspci, numactl, ethtool, iostat, perf, nvidia-smi, top/htop, ipmitool.

Gives evidence for these requirements in the posting:

  • Linux tools: dmesg, journalctl, lspci, numactl, ethtool, iostat, perf, nvidia-smi, ipmitool

New to linux and containers? Read the 5-minute primer first.

What done looks like

Deliverable. triage.sh plus a table: symptom, command, how to read the output.
The outcome, step by step (field manual version)
  1. For each resource (CPU, memory, disk, network, GPU) write the three USE questions: utilization, saturation, errors.
  2. Run the first-minute set on any Linux VM: uptime, dmesg -T | tail, vmstat 1, mpstat -P ALL 1, pidstat 1, iostat -xz 1, free -m, sar -n DEV 1, ethtool -S <nic>. On a GPU box add nvidia-smi dmon.
  3. Create one bottleneck at a time with stress-ng (CPU, memory), fio (disk) and iperf3 (network). Write down which tool exposes each one first.
  4. Wrap the set into triage.sh that prints a one-page report with a verdict line per resource.

Hands-on steps

  1. Install the tools (already done in S2 - run again to be sure).
    sudo apt install -y sysstat stress-ng fio iperf3 ethtool
  2. Run the 'first minute' set on an idle system and save it as your baseline. Read each output: what is the column that matters?
    uptime                 # load average vs CPU count (nproc)
sudo dmesg -T | tail -20   # kernel errors, OOM kills, NIC resets
vmstat 1 5             # r = run queue, si/so = swapping, wa = I/O wait
mpstat -P ALL 1 3      # per-CPU %usr %sys %iowait %idle
pidstat 1 3            # which process uses CPU
iostat -xz 1 3         # %util, r_await/w_await per disk
free -m                # look at 'available', not 'free'
sar -n DEV 1 3         # rxkB/s txkB/s per NIC
ethtool -S eth0 | grep -iE 'err|drop'   # NIC error counters (name may differ: ip -br link)
  3. Bottleneck 1 - CPU. In terminal 1 run the load, in terminal 2 watch.
    stress-ng --cpu 0 --timeout 60s          # terminal 1
vmstat 1    # terminal 2: 'r' climbs above nproc, 'id' near 0
mpstat -P ALL 1
  4. Bottleneck 2 - Memory.
    stress-ng --vm 2 --vm-bytes 85% --timeout 60s
vmstat 1    # watch free drop, si/so > 0 if swapping
free -m
  5. Bottleneck 3 - Disk.
    fio --name=randw --rw=randwrite --bs=4k --size=1G --numjobs=4 --iodepth=32 \
    --ioengine=libaio --direct=1 --runtime=60 --time_based --filename=/tmp/fio.test
iostat -xz 1   # %util near 100, w_await grows
rm -f /tmp/fio.test
  6. Bottleneck 4 - Network (loopback in WSL; between the two VMs of S7 for a real NIC).
    iperf3 -s &          # server
iperf3 -c 127.0.0.1 -t 30
sar -n DEV 1
  7. Write triage.sh - one command, one page, one verdict per resource. Start from this skeleton and improve it.
    cat > ~/gpu-lab/linux/triage.sh <<'EOF'
#!/usr/bin/env bash
# 60-second triage: prints a verdict per resource. Usage: ./triage.sh
set -u
N=$(nproc)
echo "== $(hostname)  $(date -Is)  cpus=$N"
LOAD=$(awk '{print $1}' /proc/loadavg)
RQ=$(vmstat 1 3 | tail -1 | awk '{print $1}')
IDLE=$(vmstat 1 3 | tail -1 | awk '{print $15}')
SWAP=$(vmstat 1 3 | tail -1 | awk '{print $7+$8}')
AVAIL=$(free -m | awk '/Mem:/ {printf "%d", $7/$2*100}')
echo "CPU   : load=$LOAD runq=$RQ idle=${IDLE}% -> $( [ "$RQ" -gt "$N" ] && echo SATURATED || echo ok)"
echo "MEM   : available=${AVAIL}% swap_io=$SWAP -> $( [ "$AVAIL" -lt 10 ] || [ "$SWAP" -gt 0 ] && echo PRESSURE || echo ok)"
DISK=$(iostat -dxz 1 2 | awk '/^[a-z]/ && $1!="Device" {u=$NF} END {print u+0}')
echo "DISK  : max_util=${DISK}% -> $( awk -v d=$DISK 'BEGIN{print (d>80)?"SATURATED":"ok"}')"
ERR=$(sudo dmesg -T 2>/dev/null | grep -ciE 'error|fail|oom|xid' || true)
echo "KERNEL: dmesg error-ish lines=$ERR -> $( [ "$ERR" -gt 0 ] && echo CHECK || echo ok)"
if command -v nvidia-smi >/dev/null; then
  nvidia-smi --query-gpu=index,utilization.gpu,temperature.gpu,power.draw,clocks_event_reasons.active --format=csv,noheader \
   | sed 's/^/GPU   : /'
fi
EOF
chmod +x ~/gpu-lab/linux/triage.sh && ~/gpu-lab/linux/triage.sh
You should see. Idle: all 'ok'. Under stress-ng --cpu: CPU SATURATED. Under --vm: MEM PRESSURE. Under fio: DISK SATURATED. Each tool exposes its bottleneck within a few seconds.

Interview

Be ready for: A node is slow. What do you run first, second and third, and what does each rule out?

Show the answer you can now give

A node is slow. I run uptime, dmesg, vmstat, mpstat, pidstat, iostat, free, sar -n DEV in that order - USE method: utilization, saturation, errors per resource - and on a GPU box add nvidia-smi and clock-event reasons. Each one rules out a layer in seconds.
