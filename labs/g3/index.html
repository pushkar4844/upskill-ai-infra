Why it matters

Compute and networking infrastructure at hyperscalers or cloud service providers.

Gives evidence for these requirements in the posting:

  • Stand-out: hyperscaler compute and networking knowledge

New to slurm and provisioning? Read the 5-minute primer first.

What done looks like

Deliverable. Comparison matrix plus a post-mortem of your build.
The outcome, step by step (field manual version)
  1. Pick one Slurm cluster recipe each from AWS, Azure and Google Cloud repos and read their network and storage choices side by side.
  2. Build at least one for real with IaC, then record time-to-first-job and every failure you hit.
  3. Note how each exposes health checks and replacement of bad nodes.
  4. Summarize in a matrix: provisioning tool, image build, scheduler, interconnect, storage, health tooling.

Hands-on steps

  1. AWS ParallelCluster: install the CLI and create a tiny Slurm cluster with 1-2 GPU nodes (use spot, small max count).
    python3 -m venv ~/pc && . ~/pc/bin/activate && pip install aws-parallelcluster
pcluster version
pcluster configure --config cluster.yaml     # pick Slurm, a GPU queue, max 2 nodes, EFA if type supports
pcluster create-cluster -n lab -c cluster.yaml
pcluster describe-cluster -n lab
  2. Time to first job; run nccl-tests; record every failure you hit.
  3. Read Azure CycleCloud Slurm + azurehpc-health-checks and Google Cluster Toolkit blueprints (Go deeper). Fill the matrix: provisioning tool, image, scheduler, interconnect, storage, health tooling.
  4. Delete.
    pcluster delete-cluster -n lab
You should see. A working ParallelCluster Slurm with GPU compute nodes; a comparison matrix for 3 clouds.

Interview

Be ready for: Compare how three clouds expose the GPU fabric to a customer.

Show the answer you can now give

AWS exposes EFA via libfabric + aws-ofi-nccl, Azure uses InfiniBand on HB/ND VMs, Google uses its own GPU NICs/GPUDirect variants per machine type - so NCCL plugins, tuning and health checks differ even with the same GPU.
