Why it matters

Analyze deployment data and identify operational risks; reduce manual break-fix.

New to gpu health and diagnostics? Read the 5-minute primer first.

What done looks like

Deliverable. Design note with screenshots of the quarantine, drain and remediation flow.
The outcome, step by step (field manual version)
  1. Read the NVSentinel overview. List its monitors: GPU health (DCGM), syslog, cloud provider events, Kubernetes object monitor.
  2. Deploy it on a single-GPU Kubernetes node following the docs.
  3. Write one fault-quarantine rule in CEL and read how the circuit breaker prevents mass quarantine during cluster-wide events.
  4. Try to simulate a fault event. Record what you could simulate and what needs real hardware faults.
  5. Write a design note: when to reset one GPU versus reboot the node versus RMA.

Hands-on steps

  1. On the k3s GPU node from H1, follow the NVSentinel docs to install it (Helm). Record each component it deploys.
    git clone https://github.com/NVIDIA/NVSentinel && ls NVSentinel && less NVSentinel/README.md
  2. List monitors (GPU health via DCGM, syslog, cloud events, K8s objects) and the remediation flow (quarantine -> drain -> remediate) with the circuit breaker.
  3. Write one quarantine rule in CEL following their examples; try to trigger it (e.g. inject a fake syslog XID line with logger -p kern.err 'NVRM: Xid (PCI:0000:00:1e): 79, test' if the syslog monitor reads it).
    logger -p kern.err 'NVRM: Xid (PCI:0000:00:1e): 79, pid=0, test injected'
kubectl get nodes   # watch for cordon/taint
  4. Design note: GPU reset vs node reboot vs RMA, and how the circuit breaker prevents draining the cluster during a fleet-wide event.
You should see. Components running; either a quarantine event from your injected line or a clear note of what needs real faults.

Interview

Be ready for: A node reports a recoverable GPU fault. Reset the GPU or reboot the node, and how do you decide?

Show the answer you can now give

Recoverable fault (e.g. XID 63, 94): drain and reset the GPU at a safe point. Bus or firmware faults (79, 119): reboot the node. Repeats on the same GPU or row-remap failures: RMA. A circuit breaker stops remediation when too many nodes fail at once - that's a fleet problem, not a node problem.
