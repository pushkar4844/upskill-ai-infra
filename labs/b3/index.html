Burn-in and thermal or power throttling

New GPUs are stressed for hours before customers get them. Learn to burn in, log clocks/temps/power, and spot throttling.

Why it matters

Power and thermal envelopes; identify issues during early-stage bring-up.

Gives evidence for these requirements in the posting:

  • Bring-up and validation of multi-GPU and multi-node NVIDIA platforms
  • CUDA, NCCL, NVSwitch/NVLink, drivers, performance tuning
  • Server hardware: PCIe, firmware, NUMA, BIOS/UEFI, power and thermal

New to gpu health and diagnostics? Read the 5-minute primer first.

What done looks like

Deliverable. burn-in report with plots and the pass rule.
The outcome, step by step (field manual version)
  1. Run gpu-burn for at least 30 minutes on every GPU. Run Hugging Face gpu-fryer as a second opinion.
  2. Log temperature, power, SM clock and clock event reasons every second with nvidia-smi dmon or the query interface.
  3. Plot time series. Identify where clocks drop and which reason is flagged (HW slowdown, power brake, thermal).
  4. Run cuda_memtest to look for memory faults the stress test can miss.
  5. Define a pass rule, for example: no uncorrectable ECC, no sustained HW slowdown, temperature below your threshold, clocks within a band of the median GPU.

Hands-on steps

  1. Build gpu-burn.
    git clone https://github.com/wilicc/gpu-burn && cd gpu-burn && make
  2. Start logging every second, then burn for 30 minutes.
    nvidia-smi --query-gpu=timestamp,index,temperature.gpu,power.draw,power.limit,clocks.sm,clocks_event_reasons.active,ecc.errors.uncorrected.volatile.total --format=csv -l 1 > burn.csv &
./gpu_burn 1800
kill %1
# older drivers: field name is clocks_throttle_reasons.active
  3. Make throttling happen on purpose by lowering the power limit, burn again 5 minutes.
    nvidia-smi -q -d POWER | grep -i 'limit'
sudo nvidia-smi -pl 50     # watts; pick something below default
./gpu_burn 300
sudo nvidia-smi -pl <default>
  4. Memory test.
    git clone https://github.com/ComputationalRadiationPhysics/cuda_memtest && cd cuda_memtest && mkdir build && cd build && cmake .. && make -j && ./cuda_memtest --stress --num_passes 1
  5. Plot burn.csv (temperature, power, SM clock over time) and mark where clocks drop. Decode the clock-event bitmask (nvidia-smi -q -d PERFORMANCE explains reasons). Write your pass rule.
  6. Optional second opinion: Hugging Face gpu-fryer (README for build/run).
You should see. Steady clocks at default power; under a low power cap SM clock drops and the 'SW Power Cap' reason is active. No uncorrected ECC.

Interview

Show the answer you can now give

I burn in for hours with gpu-burn plus a memory test, log clocks/temp/power/event reasons per second, and fail a GPU for uncorrectable ECC, sustained HW slowdown, or clocks well below the median of its peers.
