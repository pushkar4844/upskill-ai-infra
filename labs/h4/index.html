Gang scheduling, quota and topology on fake nodes

Practice multi-tenant GPU scheduling (quota, borrowing, all-or-nothing start) with 100 fake GPU nodes on a laptop.

Why it matters

Kubernetes for distributed workloads; large-scale bring-up and operational workflows.

New to kubernetes for gpus? Read the 5-minute primer first.

What done looks like

Deliverable. Manifests, a screen capture of preemption and gang start, and a comparison table.
The outcome, step by step (field manual version)
  1. Create a kind cluster and add fake GPU nodes with KWOK that advertise nvidia.com/gpu capacity and topology labels.
  2. Install Kueue and define a ClusterQueue per team with GPU quota and borrowing.
  3. Submit a multi-pod JobSet that must start together. Show that a partial allocation does not start.
  4. Repeat with KAI Scheduler or Volcano and compare behavior. Read LeaderWorkerSet for serving groups.
  5. Use the scheduler simulator to replay a placement decision and explain it.

Hands-on steps

  1. kind cluster + KWOK (fake nodes). Use the latest release tag from the KWOK GitHub page.
    kind create cluster --name sched
KWOK=$(curl -s https://api.github.com/repos/kubernetes-sigs/kwok/releases/latest | jq -r .tag_name)   # v0.8.0 on Oct 8, 2026
kubectl apply -f https://github.com/kubernetes-sigs/kwok/releases/download/$KWOK/kwok.yaml
kubectl apply -f https://github.com/kubernetes-sigs/kwok/releases/download/$KWOK/stage-fast.yaml
  2. Create 16 fake 8-GPU nodes in 2 racks.
    for i in $(seq 1 16); do rack=$(( (i-1)/8 )); cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Node
metadata:
  name: gpu-$i
  annotations: { kwok.x-k8s.io/node: fake }
  labels: { type: kwok, topology.kubernetes.io/zone: rack-$rack, nvidia.com/gpu.product: H100 }
spec:
  taints: [{ key: kwok.x-k8s.io/node, value: fake, effect: NoSchedule }]
status:
  allocatable: { cpu: "96", memory: 1Ti, pods: "110", nvidia.com/gpu: "8" }
  capacity:    { cpu: "96", memory: 1Ti, pods: "110", nvidia.com/gpu: "8" }
EOF
done
kubectl get nodes
  3. Install Kueue (latest release) and define two teams with GPU quota and borrowing. Kueue v0.20 removed the v1beta1 API, so use v1beta2 (where cohort is now cohortName).
    KUEUE=$(curl -s https://api.github.com/repos/kubernetes-sigs/kueue/releases/latest | jq -r .tag_name)   # v0.20.1 on Oct 8, 2026
kubectl apply --server-side -f https://github.com/kubernetes-sigs/kueue/releases/download/$KUEUE/manifests.yaml
kubectl -n kueue-system wait deploy/kueue-controller-manager --for=condition=Available --timeout=180s
cat > kueue.yaml <<'EOF'
apiVersion: kueue.x-k8s.io/v1beta2
kind: ResourceFlavor
metadata: { name: h100 }
spec: { nodeLabels: { nvidia.com/gpu.product: H100 }, tolerations: [{ key: kwok.x-k8s.io/node, operator: Exists, effect: NoSchedule }] }
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: ClusterQueue
metadata: { name: team-a }
spec:
  cohortName: lab
  namespaceSelector: {}
  resourceGroups:
  - coveredResources: [cpu, memory, nvidia.com/gpu]
    flavors:
    - name: h100
      resources:
      - { name: cpu, nominalQuota: 1000 }
      - { name: memory, nominalQuota: 10Ti }
      - { name: nvidia.com/gpu, nominalQuota: 64, borrowingLimit: 32 }
---
apiVersion: kueue.x-k8s.io/v1beta2
kind: LocalQueue
metadata: { name: team-a, namespace: default }
spec: { clusterQueue: team-a }
EOF
kubectl apply -f kueue.yaml   # copy the ClusterQueue as team-b too
  4. Submit a 4-pod job that needs 4x8 GPUs and must start together (Kueue admits the whole workload or nothing). Then submit more than the quota and watch queueing/preemption.
    cat > job.yaml <<'EOF'
apiVersion: batch/v1
kind: Job
metadata: { name: train-32gpu, labels: { kueue.x-k8s.io/queue-name: team-a } }
spec:
  parallelism: 4
  completions: 4
  suspend: true
  template:
    spec:
      restartPolicy: Never
      tolerations: [{ key: kwok.x-k8s.io/node, operator: Exists, effect: NoSchedule }]
      containers:
      - name: w
        image: busybox
        command: [sleep, "300"]
        resources: { requests: { nvidia.com/gpu: 8, cpu: 1, memory: 1Gi }, limits: { nvidia.com/gpu: 8 } }
EOF
kubectl apply -f job.yaml
kubectl get workloads; kubectl get pods -o wide
  5. Repeat with KAI Scheduler or Volcano and compare; read JobSet and LeaderWorkerSet; use kube-scheduler-simulator to inspect a decision (Go deeper).
You should see. Workload admitted only when 32 GPUs are free; pods land on fake nodes; extra jobs wait in queue; borrowing lets team-a use team-b's idle quota.

Check yourself

If it breaks

SymptomFix
Pods Pending: untolerated taintAdd the kwok toleration to pod spec and ResourceFlavor
Workload not createdJob needs the queue-name label and Kueue's webhook must be running

Still stuck? Follow the debug ladder.

Commit and clean up

Clean up

kind delete cluster --name sched

Interview

Be ready for: Two teams share 256 GPUs. How do you enforce quota and keep gangs from deadlocking?

Show the answer you can now give

Quota per team with ClusterQueues and a cohort for borrowing; all-or-nothing admission (gang) so partial jobs don't hold GPUs and deadlock; topology labels so gangs land in one rack or NVLink domain.

Go deeper

Hidden gem. KWOK lets you test scheduler behavior at scale on a laptop. It is the best free way to practice multi-tenant GPU scheduling.
