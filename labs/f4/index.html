Find the bad node by bisection

Find one slow node among hundreds without testing every pair. Build it as a simulation first, then run it for real under Slurm.

Why it matters

Identify bottlenecks at cluster, node, accelerator and network layers.

Gives evidence for these requirements in the posting:

  • Bring-up and validation of multi-GPU and multi-node NVIDIA platforms

New to nccl and collectives? Read the 5-minute primer first.

What done looks like

Deliverable. bisect_nodes.py plus a simulated run with a planted bad node.
The outcome, step by step (field manual version)
  1. Write a script that runs two-node all-reduce across pairs from a node list under Slurm.
  2. Implement group testing: split into groups, test, then re-test failing groups with smaller membership until the suspect set stops shrinking.
  3. Output a suspect list with evidence (busbw, errors seen, XIDs on the node).
  4. Compare with NVCRE's Diagnose mode, which does adaptive fault isolation down to a minimum group size.
  5. Add a Slurm health check hook so a flagged node is drained automatically.

Hands-on steps

  1. Simulation on your laptop: a fake 'run_allreduce(nodes)' returns low busbw if a planted bad node is in the group.
    cat > ~/gpu-lab/nccl/bisect_nodes.py <<'EOF'
#!/usr/bin/env python3
"""Group-testing bisection to find slow nodes. Replace run_allreduce() with a real Slurm/nccl-tests call."""
import random
NODES = [f"node{i:03d}" for i in range(200)]
BAD = set(random.sample(NODES, 1))
TESTS = 0
def run_allreduce(group):          # returns busbw GB/s
    global TESTS; TESTS += 1
    return 40.0 if BAD & set(group) else 90.0
def bisect(group, thresh=80, min_size=2):
    if run_allreduce(group) >= thresh: return []
    if len(group) <= min_size: return group
    mid = len(group)//2
    return bisect(group[:mid], thresh, min_size) + bisect(group[mid:], thresh, min_size)
suspects = bisect(NODES)
print('planted:', BAD, 'suspects:', suspects, 'tests run:', TESTS)
EOF
python3 ~/gpu-lab/nccl/bisect_nodes.py
  2. Note the subtlety: a group of 1 can't run all-reduce - pair a suspect with a known-good node to confirm. Extend the script to do that.
  3. Real version: run_allreduce() submits srun -N <len> --nodelist=<group> all_reduce_perf ..., parses busbw, and also greps each node's dmesg for XIDs. Use the Slurm cluster from G3 or the 2-node pair.
  4. Add a Slurm hook: flagged node -> scontrol update nodename=X state=drain reason='bisect-slow'.
  5. Compare with NVCRE's Diagnose mode (adaptive fault isolation).
You should see. Finds the planted node in ~log2(200) x 2 tests (~15-20) instead of 200 pairs.

Interview

Be ready for: One node out of 200 slows every all-reduce. How do you find it without testing all 200 pairs?

Show the answer you can now give

One slow node in 200: split into groups, run all-reduce per group, recurse into groups below threshold, confirm suspects paired with known-good nodes - about log2(N) rounds instead of N-squared pairs, then drain the node and check its XIDs, NIC counters and PCIe.
