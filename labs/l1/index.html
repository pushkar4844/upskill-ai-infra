Capstone: GPU Bring-up and Validation Kit

One repository, one command: Terraform builds a 2-node GPU cluster, Ansible configures it, your acceptance stages run, a report comes out.

Where

What done looks like

Deliverable. Public repository with CI that regenerates the sample report from stored outputs.
The outcome, step by step (field manual version)
  1. Layout: terraform/ (network, placement group, security group allowing self traffic, nodes), ansible/ (driver, DCGM, EFA or OFED, container toolkit, nccl-tests, node health check), tests/ (the B5 stages), criteria.toml, reports/.
  2. One command builds a 2-node cluster, runs all stages and writes a signed-off or failed report.
  3. Add a Kubernetes path with the GPU Operator and the Cluster Readiness Engine as a second validation method.
  4. Add a runbook for each failure you injected: XID simulated line, down-trained link, wrong NUMA binding, EFA disabled.
  5. README: architecture diagram, results table, cost per validation run, and what you would do differently at 2,000 GPUs.

Hands-on steps

  1. Layout.
    capstone/
  terraform/        # S9 efa2 module: VPC/SG self-traffic, placement group, 2 nodes
  ansible/          # driver check, DCGM, EFA/NCCL, container toolkit, nccl-tests, NHC
  stages/           # from B5
  criteria.toml
  reports/
  Makefile          # make up / make validate / make report / make down
  README.md
  2. Makefile targets.
    up:       ; cd terraform && terraform apply -auto-approve
configure:; cd ansible && ansible-playbook -i inventory.aws_ec2.yml site.yml
validate: ; python3 run_acceptance.py --criteria criteria.toml --out reports/$$(date +%F)
down:     ; cd terraform && terraform destroy -auto-approve
  3. Ansible: dynamic inventory (amazon.aws.aws_ec2 plugin, filter tag Name=lab-efa-*), connect via SSM (community.aws.aws_ssm connection) so no SSH port is needed.
  4. Inject failures and write a runbook for each: simulated XID line, EFA disabled (NCCL_NET=Socket), wrong NUMA binding, a 'slow node' (power cap with nvidia-smi -pl).
  5. Optional K8s path: k3s + GPU Operator + Cluster Readiness Engine as a second validator.
  6. README: architecture diagram, results table, cost per validation run, what changes at 2,000 GPUs.
  7. CI (GitHub Actions): lint Terraform/Ansible/Python and regenerate the sample report from stored outputs (no GPUs in CI).
You should see. make up && make configure && make validate && make down produces a dated report in ~1-2 hours for ~$20.

Interview

Be ready for: Walk me through your validation kit: what it checks, what it caught, what it cost.

Show the answer you can now give

My kit builds a 2-node EFA cluster with Terraform, configures it with Ansible, runs DCGM, burn-in, NCCL single and multi-node, RDMA and storage stages against thresholds in a criteria file, and writes a go/no-go report. It caught EFA fallback, a power-capped straggler and a NUMA mis-binding; a run costs about $20.
