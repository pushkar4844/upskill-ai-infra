GPU Operator on one node

On Kubernetes, NVIDIA's GPU Operator installs everything a node needs for GPUs. Learn what it deploys, in what order, and how a pod gets a GPU.

Where

Time
6 hours
Cost
~$1-2

Why it matters

Containers and drivers; Kubernetes for GPU workloads.

Gives evidence for these requirements in the posting:

  • Linux fundamentals: drivers, kernel subsystems, cgroups, containers

New to kubernetes for gpus? Read the 5-minute primer first.

What done looks like

Deliverable. Helm values, a pod spec and a diagram of operator components.
The outcome, step by step (field manual version)
  1. Install a single-node Kubernetes (k3s or kind with GPU passthrough where possible) and the GPU Operator via Helm.
  2. List what it deploys: driver, container toolkit, device plugin, GPU feature discovery, DCGM exporter, node feature discovery.
  3. Run a CUDA sample pod and read kubectl describe node for nvidia.com/gpu capacity and labels.
  4. Redo with a preinstalled driver and the driver container turned off. Note the differences.

Hands-on steps

  1. Start a GPU instance and install k3s (single-node Kubernetes) + helm.
    cd ~/gpu-lab/infra/gpu1 && terraform apply
aws ssm start-session --target $(terraform output -raw id); sudo -iu ubuntu
curl -sfL https://get.k3s.io | sh -
sudo chmod 644 /etc/rancher/k3s/k3s.yaml && echo 'export KUBECONFIG=/etc/rancher/k3s/k3s.yaml' >> ~/.bashrc && source ~/.bashrc
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
kubectl get nodes
  2. Install the GPU Operator. The DL AMI already has the driver, so turn off the driver container. k3s uses its own containerd paths - check the GPU Operator docs ('Getting started' > K3s) for the current values. Recent GPU Operator releases (v26.x) need containerd 2.0 and restart containerd when they apply config, so expect a short blip.
    helm repo add nvidia https://helm.ngc.nvidia.com/nvidia && helm repo update
helm install gpu-operator nvidia/gpu-operator -n gpu-operator --create-namespace --wait \
  --set driver.enabled=false \
  --set toolkit.env[0].name=CONTAINERD_CONFIG --set toolkit.env[0].value=/var/lib/rancher/k3s/agent/etc/containerd/config.toml \
  --set toolkit.env[1].name=CONTAINERD_SOCKET --set toolkit.env[1].value=/run/k3s/containerd/containerd.sock
kubectl get pods -n gpu-operator -w      # wait until all Running/Completed
  3. See what it deployed and what the node now advertises.
    kubectl get ds -n gpu-operator
kubectl describe node | grep -A3 -E 'nvidia.com/gpu|Capacity'
kubectl get node -o json | jq '.items[0].metadata.labels | with_entries(select(.key|startswith("nvidia.com")))'
  4. Run a GPU pod.
    cat > cuda-pod.yaml <<'EOF'
apiVersion: v1
kind: Pod
metadata: { name: cuda-test }
spec:
  restartPolicy: Never
  runtimeClassName: nvidia        # remove this line if the pod fails with 'runtimeclass not found'
  containers:
  - name: cuda
    image: nvcr.io/nvidia/cuda:12.4.1-base-ubuntu22.04   # any CUDA base tag that exists on NGC
    command: ["nvidia-smi"]
    resources: { limits: { nvidia.com/gpu: 1 } }
EOF
kubectl apply -f cuda-pod.yaml && sleep 20 && kubectl logs cuda-test
  5. Draw the components: node-feature-discovery -> GPU feature discovery (labels) -> container toolkit -> device plugin (advertises nvidia.com/gpu) -> DCGM exporter -> validator. Note what the driver container would add on a bare node.
  6. Destroy.
    terraform destroy -auto-approve
You should see. All gpu-operator pods Running/Completed, node capacity nvidia.com/gpu: 1, labels like nvidia.com/gpu.product=Tesla-T4, and kubectl logs cuda-test prints the nvidia-smi table.

Interview

Be ready for: What does the GPU Operator install and in what order?

Show the answer you can now give

The GPU Operator installs driver (optional), container toolkit, device plugin, GPU feature discovery, DCGM exporter and validators as DaemonSets. The device plugin advertises nvidia.com/gpu; when a pod requests it, kubelet allocates a GPU and the NVIDIA runtime injects the device nodes and driver libraries.
