Study guide

How to use this roadmap

Work through the phases in order. Inside a phase, do the labs top to bottom: each one builds on the labs before it.

How to use this roadmapWeekly plansFirst 10 daysEnvironments & cost

The structure

  • Phases are stages of the journey (Setup → Foundations → Practitioner → Senior → Capstone). Each has a goal and a checkpoint.
  • Modules group a phase's labs by topic, for example “GPU health and diagnostics”.
  • Labs are 2–20 hour hands-on tasks with commands, expected output, self-checks, fixes and an interview answer.
  • Concept primers explain each of the 12 topics in five minutes. Read one before a topic's first lab.

Who this is for

Assumed background: comfortable with Linux, containers and Kubernetes, infrastructure as code, and at least one hyperscaler's compute and networking, plus experience delivering projects across several teams.

What it fills in: hands-on GPU diagnostics, RDMA and NCCL, PCIe/NUMA/BIOS, BMC and Redfish, bare-metal provisioning: the hardware and fabric layers a cloud background usually skips.

New to Kubernetes or Terraform? Do a short intro course on each before Phase 1; the labs assume the basics.

A session, start to finish

  1. 1Pick

    Open the roadmap; “Continue” takes you to your next unfinished lab.

  2. 2Read

    Why it matters, what done looks like, the primer if the topic is new.

  3. 3Bring up

    Create the environment on the lab. Note the time.

  4. 4Run

    Copy each block. Write surprises into notes/<lab>.md.

  5. 5Check

    Compare with “You should see”. Tick each self-check.

  6. 6Fix

    “If it breaks”, then the debug ladder.

  7. 7Commit

    Scripts, results, notes. Push.

  8. 8Tear down

    terraform destroy, labdown. Then say the interview answer out loud.

Insights that shape the path

Practise cheap first

Every expensive lab has a free rehearsal: Soft-RoCE before EFA, Redfish mockups before real BMCs, Slurm in Docker and KWOK fake GPUs before real clusters. Rent big hardware only to measure.

Evidence over reading

Each lab ends with an artifact in your repo: a script, a report, a plot. Fifty small artifacts are more convincing than any certificate.

Collect failures

Write every failure down as symptom, cause, fix. Interviewers for infrastructure roles ask for debugging stories more than anything else.

Lab tiers, so cost stays low

  • Tier 0: laptop or one VM. Soft-RoCE, Redfish mockups, OpenBMC in QEMU, Slurm in Docker, KWOK fake GPU nodes.
  • Tier 1: one GPU instance on spot.
  • Tier 2: one multi-GPU node.
  • Tier 3: two or more EFA or InfiniBand nodes for a few hours. Tear down every night.

Advice from a practitioner

From a mentoring conversation with an NVIDIA Sr. Solutions Architect (AI Inference): learn LLM basics at a light level, go deep on how workloads are deployed on Kubernetes, think about storage close to compute, topology-aware GPU placement, Kubernetes security (admission policy), CRDs and operators, NVIDIA's free courses.

That role is inference-focused. The Infrastructure posting is closer to hardware bring-up, so those items became H4, H5, H7, H8, I3 and K1 to K4, and the hardware tasks (C, D, E) were added on top.

Honest notes. Commands follow each project's documented usage and were checked against current releases (October 2026), but they have not been run on your machine. Release tags, Helm values and package names change; where a step says “check the README / --help”, do that. Cloud prices are rough: check the current spot price and always destroy what you create.
