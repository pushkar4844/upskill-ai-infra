# upskill-ai-infra

A private, hands-on learning site for the **NVIDIA Solutions Architect, Infrastructure** role (JR2012776).
It turns two study guides, the *GPU Bring-Up Field Manual* (what to learn) and the *GPU Lab Playbook* (how to do it),
plus the full job posting into a course-style website: dashboard, learning path, 12 courses, 50 guided labs, lab setup,
the JD with a requirement-to-lab map, and resources. Hosted on GitHub Pages, with content encrypted behind a username and password.

| | |
|---|---|
| Labs | 50 (10 Beginner · 25 Intermediate · 15 Senior), 471 hours, 22-week plan from Oct 12, 2026 |
| Courses | 12 domains: Linux, GPU health, server hardware, BMC, RDMA, NCCL, Slurm, Kubernetes, cloud, observability, LLM literacy, capstone |
| Each lab | Overview (JD link, environment, time, cost) · Hands-on steps with copy-paste commands · Field-manual task · Repos & docs · Interview answer |
| Stack | Plain HTML/CSS/JS generated by a zero-dependency Node script. No framework, no `npm install`. |
| Access | Every page except the landing and sign-in pages is AES-256-GCM encrypted. See [docs/AUTH.md](docs/AUTH.md). |

## Quick start

```bash
# Node 20+ only, no dependencies
node tools/users.mjs add <username>     # creates users.local.json (git-ignored) and prints a generated password
npm run dev                             # build + serve on http://localhost:8080
```

Sign in at `http://localhost:8080/login/`. (WebCrypto needs `http://localhost` or HTTPS; opening files directly with `file://` will not work.)

## Publish to GitHub Pages

**Option A: deploy from your machine (recommended, no secrets in GitHub)**

```bash
npm run deploy        # builds with users.local.json and force-pushes dist/ to the gh-pages branch
```

Then, once: **Settings → Pages → Build and deployment → Source: Deploy from a branch → `gh-pages` / `(root)`**.
The site appears at `https://<user>.github.io/upskill-ai-infra/`.

**Option B: GitHub Actions.** Add a repository secret `SITE_USERS` (`user:password;user2:password2`), set Pages source to
*GitHub Actions*, and run the **Deploy site** workflow. See [.github/workflows/deploy.yml](.github/workflows/deploy.yml).

## Repository layout

```
content/                 source of truth (edit these)
  role/                  the job posting, verbatim (JSON with the original HTML)
  manual/                Field Manual: tasks, domains, coverage map, schedule, resources, overview
  playbook/              Lab Playbook: labs (steps/commands/checks), setup steps, environments, first 10 days, debug ladder
src/
  build.mjs              site generator: content -> dist/ (pages, encryption, keyring)
  lib/                   util.mjs (helpers, icons) · layout.mjs (header/footer/page shells) · crypto.mjs (encryption)
  assets/                css/app.css · js/auth.js (sign-in + decrypt) · js/app.js (UI) · img/
tools/
  users.mjs              add/remove/list users, print the SITE_USERS secret value
  serve.mjs              local static server for dist/
  check.mjs              builds and verifies every internal link
  deploy.mjs             build + push dist/ to gh-pages
  extract_manual.py      one-time importer used to create content/manual from the original gpu.html
docs/                    ARCHITECTURE.md · AUTH.md · CONTENT.md
.github/workflows/       optional Actions deployment
```

## Common tasks

| I want to… | Do this |
|---|---|
| Add or reset a user | `node tools/users.mjs add alice` then `npm run deploy` |
| Remove a user | `node tools/users.mjs remove alice` then `npm run deploy` |
| Fix a typo in a lab | Edit `content/playbook/labs.json` (hands-on) or `content/manual/tasks.json` (field manual), then `npm run check` |
| Add a lab | See [docs/CONTENT.md](docs/CONTENT.md) |
| Check links before publishing | `npm run check` |

## Important: who can read what

- **The deployed site** is encrypted. Without a valid username and password, pages are ciphertext.
- **This repository's `content/` folder is plain JSON.** If the repository is public, anyone can read the source content on GitHub,
  whatever the site login does. For real privacy, make the repository **private**. Publishing GitHub Pages from a private repository
  needs a paid GitHub plan (Pro/Team). Alternatively keep `main` private elsewhere and publish only the encrypted `gh-pages` output.
- Never commit `users.local.json`. It is git-ignored.
