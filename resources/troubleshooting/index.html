When you're stuck

Use the same order of checks for every failed lab.

OverviewHidden gemsReadingCertificationsWhen you're stuckGlossary
  1. Read the error, all of it

    Copy the exact message into notes/<lab>.md before changing anything.

  2. Check versions

    nvidia-smi, nvcc --version, cat /proc/driver/nvidia/version, kubectl version, helm list -A. Half of GPU problems are version mismatches.

  3. Check the logs at the right layer

    Kernel: sudo dmesg -T | tail -50, journalctl -k. Service: journalctl -u <svc> -n 100. K8s: kubectl describe pod, kubectl logs -n <ns> <pod> --all-containers. NCCL: NCCL_DEBUG=INFO.

  4. Reduce the problem

    Same command on 1 GPU / 1 node / smaller message / no container. Change one thing at a time.

  5. Search the repo issues

    GitHub > repo > Issues > search the error text. Most lab errors already have an answer there.

  6. Write it down

    Symptom, cause, fix in notes/. These become your interview stories ('a time I debugged...').

Write every failure down in notes/<lab>.md as symptom, cause, fix. After 50 labs you'll have dozens of real debugging stories, which is what interviewers ask for.
